## GitHub / Vercel setup (Next.js frontend only)

1. Extract the ZIP and upload the *contents* to your repository root. At the root you should see `package.json`, `next.config.mjs`, `src/`, `science-service/`, and `supabase/`. Do not upload a parent folder around everything.
2. **Import single project** for the Next.js application in Vercel. Root Directory: `./` (the folder containing `package.json`), Framework: Next.js, Node.js Version: **24.x**. Do not use `science-service` as the Next.js root.
3. Set `NEXT_PUBLIC_SUPABASE_URL` and `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` in the Vercel environment (Production and Preview as appropriate). Only use a **publishable** key in `NEXT_PUBLIC_*` variables. No secrets in GitHub source.
4. In a new Supabase project, run all five `supabase/migrations/*.sql` files in ascending filename order. If the database already has prior migrations, run only the not-yet-applied migrations. Back up the database first.
5. Click Deploy. Vercel will install dependencies and run `next build`. If it fails, the **first actual error** in Build Logs is the ground truth; all prior syntax-only passes were insufficient to prove compatibility.
6. Once Vercel is deployed, the DNA/Notebook frontend can use Supabase. For RDKit, Primer3, pharmacophores and Vina you also need the separate Python/Docker backend on a compute host. Add server-only `SCIENCE_SERVICE_URL` and `SCIENCE_SERVICE_SECRET` on Vercel, and the SAME secret on the compute host.

- A proper `package-lock.json` generated by `npm install` and committed only after a successful build; CI then should switch to `npm ci`.
